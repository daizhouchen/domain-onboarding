# AI 自反性 Disclaimer · AI Reflexivity Disclaimer

> **核心矛盾**：让 AI 分析"主流叙事如何运转"，但 AI 自己就是主流叙事的载体——
> 因为 AI 的训练语料就是过去若干年的主流文本。这是一个无法消除的悖论，**只能显式承认**。

---

## 为什么这一步绕不开

把领域分析交给 AI，意味着请一个**深度沉浸在主流话语中**的智能体来评论这个话语本身。
- 训练数据里**反共识 / 异端 / 非英语 / 非主流媒体的声音被系统性低估**
- 训练有 cutoff date，cutoff 之后的事件、范式迁移、共识反转**完全不在模型里**
- 模型有"流畅性偏差"——会把流畅地说出主流叙事当成"正确分析"
- 模型对"少数派但合理"的判断，置信度通常比对主流低（即使少数派可能是对的）

所以：**任何 AI 生成的领域分析，HTML 末尾必须有自反性 disclaimer。** 缺这一项 = 闸门红。

---

## 应对策略 · 5 条（必做清单）

### 策略 1 · 必标 cutoff date（精确到月份）
- 不能写"模型 knowledge cutoff 大约在 2024 年初"——必须精确到**年月**
- 在 HTML 头部和末尾**两处**显式标注
- 涉及 cutoff 之后事件时，**主动调 web search 补**或**明确说"模型不掌握"**

### 策略 2 · 显式承认覆盖不足
- "非共识 / 新兴 / 异端 / 圈外 / 非英语圈" 是模型的薄弱区
- 在每个观点章节末尾，问自己："这是主流共识吗？还是我自己挖出来的？"
- 主流共识 → 用普通语气；非共识 → 加盐："这是我从 X 出处看到的少数派观点，主流不这么认为"

### 策略 3 · 推荐 ≥3 个领域专家让用户人肉验证
- 必须**具体**：人名 + 身份 + 在哪能找到（Twitter / 播客 / 书 / 公司）
- 推荐人不能全是"主流大 V"——至少 1 个是"反共识但有 credibility"的人
- 例（向量数据库领域）：
  - **Edo Liberty**（Pinecone 创始人，AI infra 主流）
  - **Bruce Momjian**（Postgres 核心 contributor，pgvector 派代表）
  - **Frank McSherry**（Materialize 创始人，对"实时数据 + 向量"有反共识看法）

### 策略 4 · 标注哪些章节"模型最容易写错"
模型的**系统性弱点**集中在两层：
- **范式层**：模型容易把当前主流范式当作"自然律"，看不到范式正在松动
- **反身性层**：模型很难分析自己也在参与的叙事——这是镜子照镜子的悖论

在这两层的章节标题旁边加视觉标记 + tooltip：
```html
<h2>范式层 <span class="ai-weak" title="模型在这一层最容易写错。请重点验证。">⚠ AI 弱区</span></h2>
```

### 策略 5 · HTML 末尾固定 "AI 视角局限性" section
- 必须有一个独立 section（不能塞进脚注或备注）
- 放置位置：HTML 倒数第 2 个 section（最后一个是来源表）
- 字数：约 150 字标准化文本（见下方模板）

## 完整 Disclaimer HTML 模板

```html
<section class="ai-disclaimer" aria-label="AI 视角局限性">
  <h3>关于这份分析的局限性 · About AI's Blind Spots</h3>

  <p class="disclaimer-body">
    这份内容由 AI 生成。AI 不是"客观第三方"——它的训练语料**就是**过去
    若干年的主流话语，所以它在分析"主流叙事如何运转"时，自己也在使用这个叙事。
    这是一个无法消除的悖论，请你阅读时保持警惕。
  </p>

  <ul class="disclaimer-list">
    <li><strong>训练数据截止：</strong>{{cutoff_date}}（精确到月）。
        此后的事件、估值、政策变化、范式反转，模型一概不掌握。
        本文中超过 cutoff 的内容已用 <code>[需用户验证]</code> 标记。</li>

    <li><strong>系统性盲区：</strong>非共识观点、新兴范式、异端流派、
        非英语圈讨论——这些在训练语料中被低估，模型对它们的覆盖**显著不足**。</li>

    <li><strong>最容易写错的层：</strong>本文的<em>范式层</em>和<em>反身性层</em>
        是模型最容易陷入"复读主流"的地方。这两章请优先用一手源核对。</li>

    <li><strong>建议人肉验证渠道：</strong>{{verification_experts}}
        （3 位领域专家，覆盖主流 + 反共识立场）。</li>

    <li><strong>本文的反身性自陈：</strong>分析"叙事如何运转"的我，本身就是
        叙事的一部分。如果你发现某个判断"听上去太顺了、太像主流"——很可能就是。</li>
  </ul>

  <p class="disclaimer-footer">
    一份诚实的"我不知道"比一份编出来的"看上去专业"更有价值——
    所以请把这篇看作**起点而非终点**。
  </p>
</section>
```

### 占位符填充示例
```yaml
cutoff_date: "2025 年 1 月"
verification_experts: |
  <a href="https://twitter.com/edoliberty">@edoliberty</a>（Pinecone 创始人）·
  <a href="https://momjian.us">Bruce Momjian</a>（Postgres / pgvector 视角）·
  <a href="https://frankmcsherry.org">Frank McSherry</a>（实时数据反共识立场）
```

## 写作语气准则

### ✗ 错误的语气（假装客观第三方）
```
"客观地说，本领域的发展呈现以下特征……"
"综合各方信息，我们可以看出……"
"从中立角度审视……"
```
错在哪：AI 不是"中立"的——它从训练语料的角度看世界。**没有 view from nowhere**。

### ✓ 正确的语气（显式承认偏差）
```
"按照我训练数据里的主流叙事，本领域……（但请注意 cutoff 在 2025/01）"
"我能看到的资料里，X 派观点比 Y 派多——这可能是事实，也可能是语料偏差。"
"这个判断我置信度不高，因为这是 cutoff 后的事件。"
"如果你是圈内人，请用你的一手观察校准我下面的描述。"
```

## 自反性陷阱清单（写每章节时自检）

- [ ] 我有没有把"模型常识"当成"领域共识"？（这俩不是一回事）
- [ ] 我有没有把"流畅地说出来"误当成"分析正确"？
- [ ] 这一段里有没有 cutoff 之后的事件？标了吗？
- [ ] 我对反共识观点的覆盖够吗？（至少 1 个反对声音）
- [ ] 这个"主流叙事"——我是在描述它，还是在重复它？
- [ ] 如果一个圈内人读到这段，会不会觉得"这就是 AI 在背诵八股"？

---

## 必须诚实的"我不知道"

下列情形必须**显式说不知道**，不能强行写：

| 情形 | 标准用词 |
|------|----------|
| Cutoff 之后的事件 | `[模型 cutoff 之后，不掌握]` |
| 内部数据 / 未公开信息 | `[此为内部数据，模型无来源]` |
| 圈内争议但模型只见过一边 | `[这是主流叙事，反方观点请验证]` |
| 数字记不准 | `[量级正确，精确数字请查 {{ source }}]` |
| 流派归属有争议 | `[流派归属在不同语境下不同，此处采用 X 出处的分类]` |

**禁止**：编造看上去具体的细节来假装有把握。
**禁止**：把"模型不掌握"伪装成"信息有限"——这两个不一样，前者是模型问题，后者是世界问题。

## 一句话总结（写在 HTML 注释里给将来的自己）

> AI 不是讲述者，AI 是讲述者之一。
> 让用户看到讲述者的身份，比让用户相信讲述更重要。
