# 三层证据链强制规则

> 写作前必读。三层链不达标 → quality_check.py 不放行 → 不出 HTML。

## 三层各自的格式

### 事实层（Fact）

**格式**：

```
fact[N] │ 一句陈述（≤40字，只描述发生了什么）│ 来源 │ 等级（A/B/C/D）│ 时间
```

**强制字段**：

- 编号 N（全文唯一，从 1 开始）
- 一句陈述——**只能是事实**，不能含判断词（"领先"、"成功"、"颠覆"都不允许）
- 来源——具体到 URL / 论文 / 财报 / 访谈
- 等级 A/B/C/D（详见 source-grading.md 的分级）
- 时间——发生时间或发布时间

**例**：

```
fact[1] │ Pinecone 2023.4 完成 B 轮 1 亿美金，估值 7.5 亿 │ Pinecone 官方博客 + Crunchbase 交叉 │ A │ 2023-04
fact[2] │ PGVector 0.5 在 2023.7 加入 HNSW 支持 │ PGVector GitHub Release │ A │ 2023-07
fact[3] │ Milvus GitHub star 数达 26K │ GitHub 当前数据 │ A │ 2024-Q1
fact[4] │ Pinecone 2024 据传 ARR 5000 万美金 │ The Information 报道 │ B │ 2024-Q1
```

**禁忌**：

- ❌ "Pinecone 是赛道领导者" — "领导者"是判断
- ❌ "向量数据库非常重要" — 没数字、没引用
- ❌ "近年来 XX 大幅增长" — "近年来"模糊、"大幅"主观

### 机制层（Mechanism）

**格式**：

```
机制 Mn │ 一句机制陈述 │ 锚点：fact[a]+fact[b]+fact[c]（≥3）│ 同构参照（可选）
   ↓
   一段（80~200字）展开为什么 fact[a]+fact[b]+fact[c] 共同支撑这条机制
```

**强制规则**：

- 每条机制必须 cite ≥3 个事实锚点
- 锚点必须是已编号的 fact[]，不能含糊地"有研究表明"
- 展开段必须解释**为什么这几个事实共同指向这条机制**，不能只是把事实重复一遍

**例**：

```
机制 M1 │ 向量数据库的护城河来自"数据规模 × 索引质量"飞轮 │ 锚点：fact[1]+fact[3]+fact[7]+fact[12]

展开：fact[1] 显示 Pinecone 早期获得 OpenAI 联动后客户大量涌入；fact[3] 表明 Milvus
作为开源代表 star 数高但商业化弱；fact[7]（早期客户带来 PB 级数据）和 fact[12]（HNSW
在大规模数据上 recall 显著优于小规模）共同表明：早期数据规模决定索引参数调优的天花板，
索引质量又反过来吸引更多客户——这构成飞轮。Milvus 缺商业化导致数据规模断档，所以飞轮
没有像 Pinecone 那样转起来。

同构参照：传统数据库的"benchmark 排名飞轮"（Oracle vs Postgres 历史）
```

**禁忌**：

- ❌ 锚点 <3——"我观察到"不算锚点
- ❌ 展开段只是"因为 fact[1]、fact[3]、所以 M1"——没解释 fact 之间的相互作用
- ❌ 把观点伪装成机制——"M2: Pinecone 会赢"，这是观点不是机制

### 观点层（Viewpoint）

**格式**：

```
观点 Vn │ 一句判断/预测/立场陈述 │ 基于机制：M[a], M[b]
   ↓
   一段展开
   ↓
   反例事实：fact[x] 或 [新增 fact 编号]
   ↓
   证伪条件：什么情况下这个观点会被打脸
```

**强制规则**：

- 每个观点必须给**反例事实** OR **证伪条件**（最好两个都给）
- 反例事实和证伪条件**不能重复**——它们解决不同问题（详见下文）
- 观点必须基于已有机制——不能从空气里蹦出来

**例**：

```
观点 V2 │ 向量数据库作为独立品类在 5 年内会被 Postgres/Mongo/Elastic 内嵌消解 │ 基于机制：M3, M5

展开：M3 表明专用引擎的护城河来自规模 × 索引质量飞轮；但 M5 揭示通用 DB 的"功能下沉"
攻击模式可以稀释新品类的独立性。当 PGVector 性能在中等规模追平 Pinecone 时，专用品类
的存在理由被剥夺了一层。

反例事实：fact[23] Pinecone 2024 估值仍在涨——市场尚未给独立品类判死刑
反例事实：fact[34] InfluxDB 作为时序数据库证明了不是所有新品类都被通用 DB 吃掉

证伪条件：如果 2026 年仍有估值 >10 亿、纯向量检索的独立公司活得健康，本观点错。
证伪条件：如果 PGVector 在 1B 向量、QPS > 1000 上 recall 仍显著低于 Pinecone，独立
品类还能撑 5 年以上。
```

## 反例事实 vs 证伪条件（必须区分）

很多人把这两个混为一谈。它们解决的是不同问题。

| 维度 | 反例事实 | 证伪条件 |
|------|----------|----------|
| 时态 | 已经发生（指向 fact[]） | 未来可能发生 |
| 用途 | 表明你看到了反方证据但仍坚持 | 让读者知道你赌的是什么 |
| 形式 | "fact[X]：XX 已经发生，但..." | "如果 X 发生，本观点错" |

**5 个反例事实示范**：

1. 观点："新闻业已经死了" → 反例：fact[X] NYT 2023 数字订阅净增 280 万
2. 观点："硬件创业不可能" → 反例：fact[X] Anker 2022 营收破百亿
3. 观点："REITs 是稳健资产" → 反例：fact[X] 美国 mall REITs 2020 年最大单日跌 40%
4. 观点："向量数据库会被通用 DB 吃" → 反例：fact[X] Pinecone 2024 估值仍涨
5. 观点："日本动画产业老龄化" → 反例：fact[X] MAPPA 2020 后崛起，团队平均 30 岁以下

**5 个证伪条件示范**：

1. 观点："比特币 5 年内归零" → 证伪：如果 2030 年比特币市值仍 >5000 亿，错
2. 观点："Tesla Optimus 量产路线赢" → 证伪：如果 2026 年仍未达 1 万台年产，错
3. 观点："具身智能必须先有世界模型" → 证伪：如果 RT-X 路线（无显式世界模型）实现端到端可商用机器人，错
4. 观点："REITs 利率敏感" → 证伪：如果美联储再加息 200bp 而 REIT 指数不跌，错
5. 观点："独立游戏发行的关键是 Steam" → 证伪：如果未来 3 年 Top 100 独立游戏中 50% 主要收入来自非 Steam 渠道，错

**两者都给最好**——反例事实让你显得不偏激，证伪条件让你显得不油滑。

## 事实链路标注语法

写作时所有跨层引用必须用以下语法：

```
fact[N]              单引用
fact[a]+fact[b]      多引用（联合支撑）
fact[a]→机制 M1      事实导出机制
M1→V2                机制导出观点
fact[a]⊥V2           反例事实针对观点（⊥ 表示反对）
```

例：

> "embedding 通用接口（fact[1]+fact[2]→机制 M1）+ 大规模数据（fact[7]）共同形成 Pinecone 早期飞轮。但 PGVector 0.5（fact[31]→机制 M5）和 file_search（fact[33]）从两个方向攻击专用品类（M5→V2）。**反例**：fact[23]⊥V2——Pinecone 估值仍涨，市场未判死。"

这段标注让 quality_check.py 能机器扫——每个 fact[] 必须存在、每个 M 必须有 ≥3 个 fact 锚点、每个 V 必须有 ⊥ 标注。

## 事实密度量化指标（quality_check.py 会扫）

| 档位 | 最少事实锚点 | A+B 级源占比 | 机制数 | 观点数 |
|------|--------------|--------------|--------|--------|
| 闪研 ⚡ | ≥15 | ≥40% | ≥3 | ≥2 |
| 精研 📖 | ≥35 | ≥50% | ≥6 | ≥4 |
| 深研 🔬 | ≥70 | ≥60% | ≥10 | ≥7 |

不达标 → 不放行。**不允许为了凑数编事实**——宁可降档也不要伪造。

## 完整三层链示范：向量数据库的市场壁垒

> **事实层**：
>
> - fact[1]：Pinecone 2023.4 完成 B 轮 1 亿美金，估值 7.5 亿（A 级，Pinecone 官博 + Crunchbase）
> - fact[3]：OpenAI 2022.12 发布 text-embedding-ada-002，标准化 embedding 接口（A 级，OpenAI 官博）
> - fact[7]：Pinecone 早期客户中包含 Notion、Shopify 等 PB 级数据用户（B 级，Pinecone 案例 page）
> - fact[12]：HNSW 索引在 1B 向量上 recall@10 比 IVF 高 8~12 个百分点（A 级，FAISS benchmark）
> - fact[23]：Pinecone 2024 估值仍在涨（B 级，The Information 单点）
> - fact[31]：PGVector 0.5 于 2023.7 加入 HNSW（A 级，PGVector GitHub）
> - fact[33]：OpenAI 2024 推出 file_search 服务（A 级，OpenAI 官博）
>
> **机制层**：
>
> 机制 M3：向量数据库的护城河来自"数据规模 × 索引质量"飞轮（fact[3]+fact[7]+fact[12]→M3）。embedding 接口标准化（fact[3]）让任何应用都能产生向量——这扩大了入口；早期大客户带来的 PB 数据（fact[7]）让头部厂商能调优 HNSW 参数到极限；而 HNSW 在大规模上 recall 显著优于小规模的特性（fact[12]）让"调优过的索引"成为不易被复制的资产——三者构成飞轮。
>
> 机制 M5：通用数据库的"功能下沉"攻击（fact[31]+fact[33]+...→M5）。当向量检索被压缩为 Postgres 的一个扩展（fact[31]）、被压缩为 OpenAI 的一个 file_search API（fact[33]），独立品类的存在理由从"必需"变为"性能优势"——这对早期赛道是降维打击。
>
> **观点层**：
>
> 观点 V2：向量数据库作为独立品类在 5 年内会被消解到 70% 以上（基于 M3, M5）。
>
> M3 描述的飞轮在头部厂商已经转起来，但 M5 揭示的下沉攻击同时启动。两条机制赛跑，看谁先到达拐点：飞轮先到 → 独立品类活；下沉先到 → 独立品类死。当前迹象（PGVector 渗透速度 + OpenAI file_search 出现）显示下沉跑得更快。
>
> **反例事实**：fact[23]⊥V2——Pinecone 估值仍涨，市场尚未判死刑。
>
> **证伪条件**：如果 2026 年存在估值 >10 亿的纯向量检索独立公司，且其 ARR 增速 >50%，本观点错。

注意这一段：

- 7 条事实（A 级 5 条、B 级 2 条 = A 级占比 71%）
- 2 条机制，每条 ≥3 个 fact 锚点
- 1 条观点，配 1 个反例事实 + 1 个证伪条件
- 全部使用 fact[] 语法
- 没有"领先"、"颠覆"、"赋能"、"飞轮"以外的判断词（"飞轮"作为已被广泛使用的机制名是允许的，但要在第一次出现时用 fact 解释）

这就是合格的三层链。
