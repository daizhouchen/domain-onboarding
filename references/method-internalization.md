# 方法内化 · Method Internalization

> **框架是手术刀，用完收进刀鞘。**
> ——继承自 book-distiller 的核心原则

读者要看到的是**洞见**，不是你用了哪些**框架**。
凡是在正文里念框架名、报学者姓、列工具步骤的，一律当学究腔处理——quality_check.py 会扫描，不通过就返工。

---

## 核心原则

```
工具内部消化 ──→ 翻译成洞见 ──→ 给具体事实和数字 ──→ 给反例/失效条件
       ↑                                                      ↓
       └──────── 工具名/学者名/框架名留在你脑子里 ←───────┘
```

**唯一例外**：HTML 末尾**可以**有一个 `<section class="further-reading">` 叫"延伸阅读 / 分析工具索引"——
在那里**可以**列学者名、推荐书目、推荐论文。但**正文一字不能露**。

## 工具 → 洞见 翻译示范（10 组对照）

### 翻译 1：五力分析 → 利润瓶颈

```diff
✗ 烂："根据波特五力分析，本领域的进入门槛较高，但替代品威胁也不容忽视，
       同时上游议价能力较强。"

✓ 好："这个领域的进入壁垒主要来自三个方向：上游 NVIDIA 占了 90% 的训练芯片产能、
       数据要 5 年以上积累、大客户合规审核要 18 个月。但真正压制利润率的是
       第四件事——pgvector 把 80% 的简单场景拿走了。"
```

---

### 翻译 2：Wardley Map → 演化阶段

```diff
✗ 烂："应用 Wardley Map 进行演化分析，向量数据库目前处于产品阶段，
       正向商品阶段演进。"

✓ 好："2021 年，向量库还要专门部署、专门调优——那时是定制活。
       2024 年，pgvector 装了就能用、云厂自带——快变成水电了。
       两年内整个赛道向'通用'方向滑了一大格。"
```

---

### 翻译 3：创新者窘境 → 低端颠覆

```diff
✗ 烂："这是一个典型的克里斯坦森式低端市场颠覆。"

✓ 好："Pinecone 早期看不上 pgvector——'那玩意儿性能差、功能少、又不专业'。
       但 pgvector 不需要客户做架构改造、不需要新合同、不需要新预算。
       两年后，80% 用户的延迟需求被 pgvector 追上了——'够用'就够了。
       Pinecone 的客户开始流失，但他们没法降价（一降就失去 SaaS 估值），
       于是被夹在中间。"
```

---

### 翻译 4：反身性 → 自我证实链

```diff
✗ 烂："根据索罗斯的反身性理论，AI 估值具有自我强化特征。"

✓ 好："这是个自己喂自己的循环：VC 信'AI 是未来'→ 钱进 → 创业公司估值高 →
       媒体头条 → 工程师跳槽 → 巨头开高薪挖人 → 巨头报告里写'AI 投入 X 亿'→
       VC 看到更信。
       这个循环靠'故事不被打破'撑着。打断条件：第一批 AI 公司死亡名单 +
       监管硬约束 + 算力供给宽松。三个一起来时，循环反过来跑。"
```

---

### 翻译 5：双系统 → 决策模式

```diff
✗ 烂："采购决策中存在 Kahneman 系统 1 主导的认知偏差。"

✓ 好："这个领域的采购看似走 RFP 流程（看上去理性），但实际上 70% 的决策
       在第一次 demo 30 分钟内就定了——后面的对比都是为已选方案找理由。
       谁先做出来漂亮的 demo、谁的销售先建立私人关系，谁就赢。
       后面的 RFP 是仪式。"
```

---

### 翻译 6：黑天鹅/反脆弱 → 风险结构

```diff
✗ 烂："根据 Taleb 的反脆弱性框架，该资产类别尾部风险被低估。"

✓ 好："这个赛道看上去稳——年化收益 18% 持续 3 年、月度回撤都在 2% 以内。
       问题在于：稳定收益靠'永远有新进入者'。市场一旦冷场，机制就反过来——
       老用户提现 → 资产被抛 → 净值下跌 → 更多人提现。
       这是脆弱，不是稳定。看上去越稳定，崩起来越快。"
```

### 翻译 7：Perez 周期 → 范式阶段

```diff
✗ 烂："基于 Perez 的技术革命周期，AI 行业目前处于安装期向部署期的转折点。"

✓ 好："2022.11 到 2024 中，是经典的'钱比人多'阶段——估值脱离收入、
       人才价格离谱、垂直应用一周一个独角兽。
       现在三个信号同时出现：第一批 AI 应用死亡名单浮现、监管硬约束落地
       （EU AI Act）、算力短缺缓解。
       接下来 5-10 年，赚钱的不再是基础模型公司，而是把模型嵌进存量业务的
       老牌厂商——他们有客户、有数据、有渠道。"
```

### 翻译 8：博弈论 → 协调点

```diff
✗ 烂："USB-C 标准之争是一个典型的 Schelling Point 协调博弈。"

✓ 好："USB-C 不是技术最优——它就是'除了 Apple 之外所有人都默认选'的那个。
       一旦多数玩家聚焦到一个点，单家想另立门户的代价就指数级上升——
       配件厂商不跟、消费者抱怨、监管盯上。
```

### 翻译 9：网络效应 → 锁定机制

## 单边叙事检测规则

每个观点章节必须包含**反对话语标志**之一：

```
"反例…" / "证伪条件…" / "但是…" / "反过来…" / "如果…则…失效"
"也有人质疑…" / "另一种解读…" / "悖论在于…" / "不过要小心…"
"这种解释也有破绽：…"
```

quality_check.py 扫描每个 `<section class="viewpoint">` 块，**没有以上任何一个标志 = 单边叙事 = 红**。

### 反例 · 单边叙事 vs 双边叙事

```diff
✗ 单边："Pinecone 难以维持估值，因为没有 Power、没有护城河、面临替代品。"

✓ 双边："Pinecone 难以维持当前估值，因为护城河弱、面临 pgvector 替代——
       不过，**反过来**：如果它能成为某些超大规模场景（>10 亿向量、亚毫秒延迟）
       的事实标准，仍可能在垂直市场撑住溢价。失效条件：超大规模场景被
       专用 ASIC 方案吃掉，那它彻底没有立足点。"
```

## 工具箱例外条款（HTML 末尾的延伸阅读）

唯一允许出现学者名、框架名、专业术语的地方是**末尾区域**：

```html
<section class="further-reading">
  <h3>延伸阅读 · Further Reading</h3>
  <p class="hint">如果你想验证或挑战本文的分析视角，下面是底层用到的几把刀。
     正文中我没有念它们的名字——但你可以自己去读原典。</p>
  <ul>
    <li><strong>《竞争战略》</strong> Michael Porter — 产业结构与利润分配</li>
    <li><strong>《创新者的窘境》</strong> Clayton Christensen — 低端颠覆机制</li>
    <li><strong>Wardley Maps</strong>（在线书）Simon Wardley — 演化轴 + 价值链</li>
    <li><strong>《技术革命与金融资本》</strong> Carlota Perez — 50 年范式周期</li>
    <li><strong>The Alchemy of Finance</strong> George Soros — 反身性原型案例</li>
  </ul>
</section>
```

**注意**：这一节的字数控制在 200 字以内，给链接 / 书名 / 一句作用，**不要展开讲**。
展开讲就是学究腔搬到末尾——同样违规。

## 一句话总结（写完所有章节后自我提问）

> "如果把所有学者名、框架名、定律名全删掉，我的文章还成立吗？还能让读者懂吗？"

如果答案是"成立、懂"——你做对了。
如果答案是"不成立、读不懂"——你只是在背诵框架，没有内化方法。**返工**。

## H1 / H2 / H3 命名规则（v0.2 新增）

method-internalization 管"正文里不能出现的词"。这一节管的是**章节标题**——
因为标题是读者扫读时第一眼看到的东西，标题暴露分析框架 = 整份文档暴露分析框架。

> **标题必须问题驱动 / 叙事化 / 给读者一个钩子，不能是分析框架名。**

quality_check.py 在 v0.2 会扫 H1 / H2 / H3 文本，命中以下任一词 → 直接红 → 返工。

### 标题禁忌词清单

```
事实层 / 机制层 / 观点层
反身性
结构层 / 范式层
跨领域同构 / 跨域同构 / 同构案例 / 反同构点
三层证据链
骨架·一 / 骨架·二 / 骨架·三 / 骨架·四 / 骨架·五
骨架五件套
AI 视角局限性 / 自检题
反 AI Slop
分析框架 / 分析工具 / 元透镜
现象层 / 事件层
```

> 白名单豁免：references 内部链接、tooltip 文本、`<code>` 块——这些位置出现可以，
> 因为它们不是给读者扫读的标题。

### 烂标题 → 好标题对照（10 组）

```diff
1.
✗ 烂： ## 事实层 · 关键事实清单
✓ 好： ## 这一年到底发生了什么 · 关键事件链

2.
✗ 烂： ## 机制层 · 飞轮与壁垒分析
✓ 好： ## 它到底靠什么转 · 飞轮与壁垒在哪

3.
✗ 烂： ## 反身性 · 主流叙事 vs 失效条件

5.
✗ 烂： ## 范式层 · 当前所处阶段

6.
✗ 烂： ## 跨领域同构 · 案例 1 / 案例 2
✓ 好： ## 别处的故事 · 镜照本地

7.
✗ 烂： ## 骨架·二 · 玩家地图
```

### Meta-语言 section 的处理

"自检题" / "AI disclaimer" / "信息来源" 这一类**关于这份文档的文档**（meta-语言），
**不要让它们抢主流叙事的戏**：

- AI disclaimer → 弱化为尾跋小字（~100 字），保留 `id="ai-disclaimer"` 给闸门扫
- 自检题 → 嵌入末尾 `<details>` 折叠，仅深研档显示
- 来源分级表 → 底部 `<details>` 折叠，闸门能扫到 `.source-grading-table`，但视觉上不抢

主流叙事的 10 章占据视觉中心，meta 内容退到底部折叠区——**读者读完故事再决定要不要看附录**，
而不是被附录拦在故事前面。

### 最后自检（写完所有 H2 之后）

> 把所有 H2 标题列成一行：
>
> "这是什么 · 为什么现在值得花一小时" → "它怎么走到今天" → "谁在场上 · 谁在赌什么"
> → "圈内人才懂的几件事" → "表面之下 · 几条不可变的约束" → "这是什么时期 · 异端正从边缘浮现"
> → "别处的故事 · 镜照本地" → "主流叙事 · 它如何自我强化又如何崩"
> → "接下来你应该读什么 · 信谁" → "我（AI）不知道的几件事"
>
> **读这一串，应该像读一份目录章节，不像读一份分析模板。**
> 读起来还像模板 = 返工标题。
