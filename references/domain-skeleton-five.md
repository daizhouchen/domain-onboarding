# 领域骨架五件套

> 五件套是这个 skill 的"承重墙"。少一件不算交付。每件都有产出格式 + quality bar + 常见错误。

## 总览

```
┌─────────────────┬───────────────────────────────────────────┐
│ 1. 核心概念图   │ 必懂术语 + 黑话四层分类 + 概念之间关系     │
│ 2. 玩家地图     │ 公司/人/学派/产品 + 关系类型              │
│ 3. 时间轴       │ 关键事件 + 时间尺度套利点                 │
│ 4. 矛盾结构     │ 核心争议、利益冲突、流派分歧              │
│ 5. 学习路径     │ 下一步读什么/跟谁/订阅/参会               │
└─────────────────┴───────────────────────────────────────────┘
```

---

## 1. 核心概念图

### 定义

把这个领域里"不知道就完全看不懂任何一段话"的术语挑出来，画出概念之间的关系。**不是字典**，是**网络**。

### 产出格式

每个核心概念一行：

```
术语（中/英）│ 一句话定义（≤25字）│ 与哪些概念关联 │ 黑话层级（①②③④）│ 来源等级
```

例子（向量数据库领域）：

```
embedding 嵌入 │ 把文本/图像压成定长数字向量 │ → ANN, RAG │ ② │ A
HNSW │ 一种近似最近邻索引算法，分层图 │ → recall, IVF │ ④ │ A
recall │ 检索出的真·最近邻占比 │ → ANN, latency │ ④ │ A
RAG │ 检索增强生成，先查再问大模型 │ → embedding, LLM │ ② │ A
```

例子（REITs 领域）：

```
REITs │ 不动产投资信托基金，强制 90% 分红 │ → cap rate, NOI │ ② │ A
cap rate │ NOI / 物业市值，租金回报率 │ → NOI, IRR │ ④ │ A
NAV │ 净资产值，REIT 的账面估值锚 │ → premium/discount │ ② │ A
mall REIT │ 商场类 REITs，2020 后大幅折价 │ → discretionary │ ① │ B
```

### 黑话四层分类（必须分层标注）

| 层级 | 含义 | 例（向量数据库） | 例（REITs） |
|------|------|------------------|-------------|
| ① 圈外人字面理解错的词 | 词面看上去懂，实际意思完全不同 | "向量"≠数学课的向量，是"高维稠密语义编码" | "信托"≠中国语境的信托公司 |
| ② 圈内缩写 | 不展开说圈外人查不到 | RAG / ANN / LLM | NOI / FFO / NAV |
| ③ 不同流派同义不同名 | 同一个东西不同叫法 | "向量数据库" / "vector store" / "embedding store" / "ANN engine" | "公募 REITs" / "上市 REITs" / "C-REIT" |
| ④ 只有内行说的"行话" | 圈外完全不知道的术语 | recall@10 / QPS 衰减曲线 | "AFFO 调整项" / "blend & extend" |

**质量门槛**：

- 闪研档：核心概念 ≥10 个，其中黑话四层各 ≥1 个
- 精研档：≥20 个，四层各 ≥2 个
- 深研档：≥30 个，四层各 ≥3 个，且必须画出至少一张 ASCII / SVG 概念关系图

### 常见错误

- 只列①②不列③④——意味着没接触一手内行
- 把"基础概念"（程序员都知道的"数据库"）也算进来灌水
- 关系列写"相关"而不是具体关系动词（"扩展"、"替代"、"前提"、"反例"）

## 2. 玩家地图

### 定义

谁在这个领域里"占位"——公司、个人、学派、产品、政府机构。**关键是关系，不是名单**。

### 产出格式

每个玩家一行：

```
玩家名 │ 类型（公司/人/产品/学派/机构）│ 立场/角色 │ 与谁关系（关系类型）│ 来源等级
```

**关系类型必须明确**（这是和"维基百科信息卡"的核心区别）：

```
合作 / 竞争 / 上下游 / 敌对 / 师承 / 投资 / 收购 / 监管
```

例（向量数据库）：

```
Pinecone │ 公司 │ 云原生纯向量库领头羊 │ 竞争 Weaviate, 上游 OpenAI │ A
Edo Liberty │ 人 │ Pinecone CEO，前 Yahoo Research │ - │ A
Milvus │ 产品 │ 开源代表 │ 由 Zilliz 维护，上游 ANN 学界 │ A
PGVector │ 产品 │ Postgres 扩展，威胁纯向量库存在 │ 敌对 Pinecone（功能下沉） │ A
```

例（日本动画产业）：

```
东映动画 │ 公司 │ 老牌龙头，电视动画奠基 │ 上游 各大电视台 │ A
京都动画 │ 公司 │ 高品质制作，2019 纵火事件 │ 师承 Mushi Production 体系 │ A
角川 │ 公司 │ IP 上游霸主（小说→动画→周边） │ 上下游 万代 │ A
押井守 │ 人 │ 监督，《攻壳》系作 │ 师承 龙之子→IG │ A
```

例（具身智能）：

```
Figure AI │ 公司 │ 人形机器人新贵 │ 投资来自 OpenAI/微软 │ B
Tesla Optimus │ 产品 │ 量产路线代表 │ 竞争 Figure │ B
李飞飞 World Labs │ 公司 │ 学界派创业 │ 师承 Stanford CS │ A
RT-2 / RT-X │ 产品（论文）│ Google DeepMind 的 VLA 路线 │ 学术对手 OpenVLA │ A
```

### 质量门槛

- 闪研：≥8 玩家，含 1 个"局内人才知道的关键人物"
- 精研：≥15 玩家，含至少一对明确"敌对/竞争"关系
- 深研：≥25 玩家，含 ≥1 个监管机构、≥1 个学派或思想源头

### 常见错误

- 只列大公司不列关键人——领域真正的"势"由人推动
- 关系写"相关"——等于没写
- 漏掉"敌人"和"已经死掉的玩家"——尤其是衰退期领域，黑莓/诺基亚这类"已死玩家"是教训抽取的关键

## 3. 时间轴

### 定义

这个领域是怎么走到今天的。**不是大事年表**，是**改变游戏规则的拐点**。

### 产出格式

```
年份 │ 事件 │ 改变了什么（"游戏规则改变"还是"只是新闻"）│ 来源
```

强制字段："改变了什么"——如果只是"某公司发布了某产品"，没改变规则，**不要进时间轴**。

例（向量数据库）：

```
2017 │ Transformer 论文 │ 规则改变：从此 embedding 成为通用接口 │ A
2020 │ Pinecone Y Combinator W21 批 │ 仅事件 │ A
2022.11 │ ChatGPT 上线 │ 规则改变：RAG 突然成为刚需，整个赛道引爆 │ A
2023.7 │ PGVector 0.5 支持 HNSW │ 规则改变：通用 DB 开始反攻 │ A
2024 │ OpenAI 推 file_search │ 规则改变：可能消解中间层 │ B
```

### "时间尺度套利点"——必出元素

**Time-scale arbitrage**：在领域的时间维度上，"哪些事改变了游戏规则"和"哪些事只是新闻"是不同尺度。套利点 = **多数人当成新闻、其实是规则改变的瞬间**（反过来：多数人当成规则改变、其实只是新闻的，也算套利点）。

例：

- 向量数据库：**PGVector 0.5（2023.7）**——当时被当作"开源界的小新闻"，事后看是品类被吃的起点
- 日本动画产业：**1995《新世纪福音战士》TV 版预算危机**——当时是事故，事后看是"制作委员会方式"被迫成型的转折
- REITs：**2020.4 美国 mall REIT 集体跳水**——当时是疫情冲击，事后看是"零售地产长期价值重估"

每个时间轴必须标注 ≥1 个时间尺度套利点。

### 质量门槛

- 闪研：≥5 个事件，≥1 个套利点
- 精研：≥10 个事件，≥2 个套利点
- 深研：≥20 个事件，≥3 个套利点 + 至少一段"如果当时 X 没发生，今天会怎样"的反事实推演

### 常见错误

- 罗列产品发布日（每家公司每个版本都列一行）
- 没标"规则改变 vs 仅事件"——最后变成产品发布会日历
- 漏掉"沉默事件"——某件没发生的事比某件发生的更重要（如：日本电视台一直没拆 18 点黄金档，所以才有现在的深夜动画结构）

## 4. 矛盾结构

### 定义

这个领域的**核心张力**——谁和谁结构性对立、利益怎么不一致、流派分歧在哪。**没有矛盾的领域报告 = 没读懂这个领域**。

### 产出格式

每个矛盾一段：

```
矛盾名（取一个对仗的标题）
├─ 一方立场 + 代表人/公司
├─ 另一方立场 + 代表人/公司
├─ 矛盾的根因（结构性约束/利益分配/技术路线）
├─ 现状（谁占上风 + 多少 evidence）
└─ 失效条件（什么情况下矛盾会消失或反转）
```

例（向量数据库）：

> **专用 vs 通用之争**
> - 专用派：Pinecone / Weaviate / Qdrant，主张向量检索是独立赛道
> - 通用派：PGVector / Mongo Atlas Vector / Elastic，主张向量是数据库的一个功能
> - 根因：技术上向量检索能否在通用 DB 引擎里达到专用引擎的 recall × QPS
> - 现状（2024 中）：通用派在小数据量上已平等，大数据量（>1B 向量）专用派仍领先
> - 失效条件：如果通用 DB 在 1B+ 向量上 recall@10 > 0.95、QPS > 500，专用派失去存在理由

例（日本动画产业）：

> **作家性 vs 委员会**
> - 作家派：押井守、新房昭之，主张监督个人风格优先
> - 委员会派：制作委员会制度（电视台+出版+玩具+音乐），分摊风险也分摊话语权
> - 根因：日本动画长期亏钱，单家投资风险过大，委员会是融资创新但稀释作者权
> - 现状：Netflix 入场后部分削弱委员会（直接投资单部作品），但未颠覆
> - 失效条件：如果流媒体直接投资模式跑通，委员会会被边缘化

### 质量门槛

- 闪研：≥1 个核心矛盾，含失效条件
- 精研：≥3 个核心矛盾，至少 1 个利益类、1 个技术路线类
- 深研：≥5 个矛盾，含 ≥1 个"局外人看不到的隐性矛盾"

### 常见错误

- 把"差异"当成"矛盾"——A 公司大、B 公司小不是矛盾
- 没写失效条件——意味着不知道矛盾的根因
- 漏隐性矛盾——比如学术派 vs 工程派、老兵 vs 新人，这些不会写在新闻稿里但是局内人都知道

## 5. 学习路径

### 定义

读完这份骨架后，用户**下一步去哪**。**不是给个书单**，是**给一张去人肉验证的地图**。

### 产出格式

分四类，每类至少 3 条：

```
A. 必读材料 (≥3)：书 / 论文 / 长文
   - 标题 + 作者 + 一句话为什么读这个
B. 关键人物 (≥3)：跟谁的 Twitter/Substack/B站
   - 人名 + 平台 + 立场（哪派的）+ 看什么
C. 信息源 (≥3)：订阅哪些 newsletter / Discord / 论坛
   - 名字 + 频率 + 信息密度（A/B/C）
D. 线下入口 (≥1)：哪些 conference / meetup / 圈子
   - 名字 + 频率 + 入门门槛
```

例（向量数据库）：

```
A. 必读：
   - "Billion-scale similarity search with GPUs" Johnson et al, 2017 — FAISS 论文，工程基础
   - Pinecone 官方 learn.pinecone.io — 体系化入门最快路径
   - PGVector GitHub README — 看反方观点必备
B. 关键人物：
   - @benjamin_anderson (Pinecone CTO) — 工程派
   - @JerryWang (LangChain) — 应用派
   - @AmandaAskell — 研究派+ AI 安全交叉
C. 信息源：
   - Latent Space podcast — 深度访谈，A 级
   - Vector Database Tracking Newsletter — 周更，B 级
   - r/LangChain — 应用层社区，B 级噪音多
D. 线下：
   - Vector Database Conference (VDB Con) — 年度，门槛低
```

### 质量门槛

- 闪研：A 类 ≥3，C 类 ≥1（共 ≥4 条）
- 精研：四类齐全，共 ≥10 条
- 深研：四类齐全，共 ≥15 条 + 至少 2 条"小众但高密度"信息源

### 常见错误

- 只给"显而易见的源"（《XX 入门》、维基百科）——用户能自己 Google 的不算价值
- 没标立场——给一堆链接但用户不知道哪个是哪一派
- 漏掉线下入口——线下圈子才能解锁"行话"和"局内人盲区"

## 五件套之间的关系

```
       核心概念图
          │
          ▼
       玩家地图 ←→ 时间轴
          │           │
          └─→ 矛盾结构 ←┘
                 │
                 ▼
              学习路径
```

- 概念图是地基——不懂术语连玩家是谁都看不出来
- 玩家地图和时间轴互为表里——人在时间里行动
- 矛盾结构是真正的"洞见"——前三件套是事实，矛盾结构是机制
- 学习路径让用户能自己继续走

任何一件套缺失或注水 → 整份报告塌方。
