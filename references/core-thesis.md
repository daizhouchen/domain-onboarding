# 核心宪法 · 三层证据链 + 自反性警示

> 任何时候卡壳、任何时候想偷懒、任何时候被 AI 套话诱惑——回这一页。

## 一句话

**事实 → 机制 → 观点**。每一层都要向下游负责。空有观点是耍流氓。

book-distiller 原话：

> 不能空有观点。事实支撑观点。揭示系统逻辑。事实陈述本身也要系统化。

领域速通把这句话推得更狠——因为领域比单本书更容易"假装专业"。一本书有作者、有页码、有引用；一个领域往往只有"大家都这么说"。AI 自己就是"大家都这么说"的总和——所以让 AI 评论领域，等于让庄家自己点评赌局。

## 三层各自要做什么

### 事实层（Fact）

**只描述发生了什么、谁说的、什么时候、什么数据**。不解释、不判断。

合格的事实：

- "Pinecone 2023 年 4 月完成 B 轮 1 亿美金，估值 7.5 亿（来源：Pinecone 官方博客 + Crunchbase 交叉验证）"
- "Milvus 在 GitHub 上有 2.6 万 star，主要贡献者来自 Zilliz 公司（来源：GitHub 仓库 commit history）"

不合格的"事实"（其实是混了观点的伪事实）：

- "Pinecone 是向量数据库领域的领导者" ← 这是观点，伪装成事实
- "Milvus 社区很活跃" ← 没数字，没法验证

### 机制层（Mechanism）

**事实之间是怎么互相作用的**。"为什么"和"怎么运转"在这一层。

强制规则：**每一条机制陈述必须 cite ≥3 个事实锚点**。事实少于 3 条就只是"我猜"。

例：

> 机制 M3：向量数据库的护城河主要来自"数据规模 × 查询质量"的飞轮——
> - fact[7]（Pinecone 早期客户带来 PB 级生产数据）
> - fact[12]（HNSW 索引在大规模数据上 recall 显著优于小规模）
> - fact[15]（Pinecone 在 OpenAI embedding 上线后获得首批 API 用户）
>
> 三个锚点共同支撑：早期数据 → 训练更好的索引参数 → 吸引更多客户 → 更多数据。

### 观点层（Viewpoint）

**作者的判断、预测、争议立场**。允许有立场，但**强制配反例事实或证伪条件**。

例：

> 观点 V2：向量数据库作为独立品类很可能在 5 年内被"内嵌进 Postgres / Mongo / Elastic"消解。
> - 反例事实：Pinecone 2024 估值仍在涨（fact[23]），说明独立赛道暂时没死
> - 证伪条件：如果 PGVector 在 1B 向量、QPS > 1000 的场景下 recall 仍然显著低于专用库，独立品类还能撑 5 年以上

**没反例的观点 = 单边叙事 = AI Slop**。

## 三个反面教材（不要写成这样）

### 反例 1：维基百科长版

> "向量数据库是一种用于存储和检索高维向量数据的数据库系统。它支持近似最近邻搜索（ANN），常用算法包括 HNSW、IVF、LSH 等。代表产品有 Pinecone、Milvus、Weaviate、Qdrant、Chroma 等。"

问题：所有事实都是常识，没有机制、没有观点、没有反身性。读者读完和没读一样。

### 反例 2：水稿（结构爆炸 + 事实空心）

> "向量数据库正处于爆发期，未来必将颠覆传统搜索范式。其商业价值主要体现在三个维度：技术壁垒、生态壁垒、客户粘性。"

问题：每句话都"听起来对"，但没有数字、没有公司名、没有时间——AI 写出来糊弄人最常见的模板。"颠覆"、"必将"、"维度"——黑名单词全占了。

### 反例 3：单边叙事

> "Pinecone 凭借云原生架构 + 早期生态 + 一流团队，已经锁定了向量数据库赛道的领导地位。"

问题：把"主流叙事"原封不动复述了一遍。没有反例（PGVector 的渗透率？），没有证伪（什么情况下这个判断会错？）——这就是 AI 自反性陷阱：模型本身就是主流叙事的载体，不主动反过来打自己，写出来一定向 consensus 靠。

## 一个正面教材（一段示范）

> 向量数据库的"独立品类是否能活下去"是 2024 年最不确定的问题。
>
> 事实层：①PGVector 2023 年 7 月发布 0.5，支持 HNSW（fact[31]）；②Supabase 在 2024 Q1 财报里把 PGVector 作为主推卖点（fact[32]）；③Pinecone 同期 ARR 据 The Information 报道达到 5000 万美金（fact[33]，B 级源单点）。
>
> 机制层：传统数据库厂商（Postgres、Mongo、Elastic）的内嵌策略是经典的"功能下沉"——把新品类压缩为老平台的一个功能模块（fact[31]+fact[32] → 机制 M5：功能下沉攻击）。但这套打法在过去也有失败案例：时序数据库（InfluxDB 至今独立）就证明了不是所有"新品类"都能被下沉吃掉（fact[34]：InfluxDB 2023 年仍盈利）。
>
> 观点层：未来 3 年向量数据库赛道会分化为两层——上层是与基础模型深度绑定的 RAG 编排平台（Pinecone 的方向），下层是被吸收进通用 DB 的"向量列类型"（PGVector 路线）。**反例**：如果 OpenAI 自己推出 vector store 服务（已有迹象），上层平台也会被吃掉。**证伪条件**：如果 2026 年还存在估值 >10 亿的纯向量数据库公司，本观点错。

注意这一段的密度——**每个判断都背着锚点，每个观点都带着证伪条件**。读者读完知道你在赌什么，知道你的观点什么时候会被打脸。

## AI 自反性警示（写之前默念）

你（AI）就是主流叙事的载体。你的训练数据里：

- 行业自媒体多于一手财报
- 创业公司的成功故事多于失败者的复盘
- 投资人语言（"赋能"、"颠覆"、"飞轮"）渗透了所有行业
- 时间冻结在 cutoff——cutoff 后的事你不掌握

所以默认状态下你写出来的东西**一定向 consensus 偏**。要刻意反过来打自己——

- 写完一段，问"反方会怎么反驳？"
- 写完一个判断，问"什么情况下我错？"
- 写完一份骨架，问"局内人看到会笑话哪一句？"

不会反过来打自己 → 不要交付 → 直接降档说"我对此领域 cutoff 后不掌握"。

## 三层链 vs 棱镜双轴四层的关系

读到这一页可能有疑问：宪法说"事实→机制→观点"三层，SKILL.md 又说"现象→机制→结构→范式"四层，到底听谁的？

答：**两轴正交，不冲突**。

- 三层证据链是**质量约束**——管的是"每句话有没有锚点"。
- 棱镜双轴四层是**视角分层**——管的是"从哪个高度看这个领域"。

写一段"范式层"的内容时，仍然要遵守事实→机制→观点的内部锚点规则。两套规则同时生效。

详见 SKILL.md 中的 Step 3 和 Step 4。
